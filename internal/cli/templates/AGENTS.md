# 经验复用规则（aimemo）

> 本项目主要编程语言：`<!--LANG-->`

本项目已接入 aimemo 经验库。在处理**非平凡任务**（修 bug、重构、技术选型、排查报错、新增功能）时，**必须**先检索历史经验再动手。

## 一、检索流程

1. **提取关键词**：从用户需求、报错信息、涉及文件、函数名、import 语句、配置文件提取 2-4 个最关键的关键词。优先使用技术栈名、框架名、错误类型、API 名称，而不是项目名。
2. **识别语言上下文**：判断当前项目主要编程语言（go / ts / js / py / rust / java / cpp / csharp / php / ruby 等）。
3. **主动检索（优先用 context）**：
   ```bash
   aimemo context "<任务描述>" --limit 5 --format prompt
   aimemo search "<关键词>" --limit 5
   aimemo search "<英文同义词>" --limit 5
   ```
   `context` 会排序、去重并限制长度；需要精确控制关键词时再用 `search`，中英文各搜一次结果更全。
4. **按语言与类别筛选**（见第二节规则）。
5. **提炼注入**：只取对当前问题真正有用的要点，压缩成简短清单，直接融入当前方案。
6. **按需深入**：某条特别相关时用 `aimemo get <id>` 取完整内容；用后调用 `aimemo use <id>`，有帮助或误导时调用 `aimemo feedback <id> --helpful|--wrong`。
7. **多项目隔离**：不同项目/租户用 `--workspace NAME`，默认工作区为空。

## 二、语言约束与分类规范

存储与检索经验时都必须遵守语言维度区分。

### 语言特定经验
适用范围：语法特性、标准库用法、工具链、构建配置、框架用法、性能陷阱。

- 分类：`skills/<语言>/<领域>` 或 `gotchas/<语言>/<场景>`
  - 示例：`skills/go/error-handling`、`skills/ts/react-hooks`、`gotchas/go/sqlite-concurrency`
- 标签：必须包含 `lang:<语言>`，例如 `lang:go`、`lang:ts`
- 检索时：只有当前项目语言匹配，才可优先采用

### 项目通用经验
适用范围：设计模式、架构思想、工程原则、通用调试方法论、协作流程。与具体语言无关。

- 分类：`patterns/architecture`、`patterns/general`、`workflows/general`、`decisions/general`
  - 示例：`patterns/architecture`、`workflows/general`
- 标签：标记 `lang:general`，不要添加具体语言标签
- 检索时：任何语言的项目都可参考

### 跨语言通用经验
适用范围：算法思路、性能优化思路、架构权衡、通用问题排查套路。

- 分类：`patterns/general`、`skills/general`
- 标签：`lang:general`

### 决策记录
适用范围：项目级技术选型、架构决策、依赖取舍、兼容性权衡。

- 分类：`decisions/<项目或主题>`
- 标签：`lang:general`，或 `lang:<语言>`（当决策与语言强相关）

### 检索时的语言匹配顺序
1. 当前语言的经验（`lang:<当前语言>`）—— 最优先
2. 通用经验（`lang:general` 或无语言标签且属于上述通用分类）—— 次优先
3. 其他语言的经验 —— 默认不采用，除非经验本身明确声明跨语言适用

## 三、沉淀流程（任务结束时）

任务完成后，判断本次是否产生可复用经验。必须同时满足：

- **可复用**：下次同类问题还会用到
- **有结论**：明确的做法 + 原因
- **非平凡**：超出常规文档能查到的内容
- **有具体细节**：代码、命令、配置、路径、错误信息

满足条件时：

1. **提炼**：压缩成「场景 + 问题 + 解决方案 + 注意事项」，每次最多 1-3 条
2. **候选**：列表格给出【标题、分类、类型、重要度、标签、理由、置信度(1-5)】
3. **征求同意**：展示候选并明确询问「是否同意沉淀？」，得到用户同意后才写入
4. **写入**：
   ```bash
   aimemo add --category skills/go --type important --importance 5 \
     --title "标题" --content "场景：... 方案：... 注意：..." --tag lang:go --tag 具体标签
   ```
5. **导出**（可选）：重要度 >= 4 且值得共享给人类时
   ```bash
   aimemo export-md --ids <id> --out ./markdown --overwrite
   ```

## 四、原则

- **检索优先于猜测**：宁可多搜一次，也不要重复踩已经沉淀过的坑
- **按上下文搜**：用问题描述而不是项目名当关键词最有效
- **语言匹配优先**：同等相关度下优先当前语言的经验
- **通用经验兜底**：当前语言无相关经验时再考虑通用经验
- **只用相关的**：搜出来的经验要真能解决当前问题才参考，不要全盘照抄
- **不存噪音**：闲聊、纯理论科普、一次性临时命令不入库
- **未经同意不写入**：必须先征求用户同意
